# ADR-005：`INV` 写入路径错误码固化补录（6 码）

- **状态**：Accepted（P0）
- **日期**：2026-10-17
- **决策人**：项目负责人（授权口径同 `ADR-002` / `ADR-003`）
- **关联**：`ADR-002`（成员资格规则）、`ADR-003`（上一次全量核对）、`DESIGN_REVIEW` **R54**（本次登记）、`DESIGN_BASIS §12.3`、`ERROR_CODES.md §2.6`、`M3-T09` / `M3-T11`

---

## 1. 背景

`M3-B5`（`V1.0.6` 库存三表）已收口，下一批 `B6 = M3-T09 InventoryWriteService` 要从零实现 `inventory` 模块（当前模块目录下只有 `pom.xml`，无任何 Java 文件）。

实现 `InventoryWriteService` 的 6 个写方法与 `lockBalanceAnchors` 时，按 `MODULE_BOUNDARIES §2.5` 与 `INVENTORY_WORKFLOW §5.3–§5.6 / §9`，**必然依赖**以下错误码：

| 错误码 | HTTP | 依赖场景 | 文档依据 |
| --- | --- | --- | --- |
| `INV-5004` | 404 | 调整/冲销时目标 `(warehouse_id, sku_id)` 无余额行 | `INVENTORY_WORKFLOW §5.5` 步骤 5「加载余额行」 |
| `INV-5005` | 400 | `qty_delta = 0` 或目标值非法 | `CK ck_invtxn_delta_non_zero`、`§5.5` 步骤 7 |
| `INV-5007` | 403 | `MANUAL_ADJUST` 需 `ADMIN+` | `DESIGN_BASIS §9.6`、`§5.5`「审批要求」 |
| `INV-5008` | 404 | 冲销的流水 ID 不存在（或不属于本团队） | `§5.6` 步骤 C |
| `INV-5010` | 422 | 冲销目标是 `REVERSAL` 或状态不允许 | `§5.6` 步骤 E |
| `INV-5011` | 400 | `COUNT_ADJUST` / `MANUAL_ADJUST` 未填 `reason` | `§5.5`「`reason` 必须」 |

`DESIGN_BASIS §12.3` 现仅含 `INV-5001` / `INV-5002` / `INV-5003` / `INV-5006` / `INV-5009`（5 个），上述 6 个**均不在清单内**；`ErrorCodes.java` 同样只定义了那 5 个常量。

按 `ADR-002` **规则 2**：「凡被**已实现代码**或**已发布里程碑验收项**所依赖的错误码，**必须**纳入本节清单；新码一经里程碑实测使用，须在**同一里程碑内**同步纳入。」

- `B6` 一旦实现即构成「已实现代码依赖」；
- `ACCEPTANCE_CRITERIA §3.4` 的 M3 验收项（盘点调整 `AC-INV-03`、负库存拦截 `AC-INV-06`、`INV-05` 幂等）已发布，其中盘点/冲销路径语义即由上述码承载。

故**必须在 `B6` 动工前**完成纳入，否则整批交付都会踩在"使用未固化错误码"的红线上。

## 2. 决策

一次性将 **6 个** `INV` 码纳入 `DESIGN_BASIS §12.3` 清单：

`INV-5004`、`INV-5005`、`INV-5007`、`INV-5008`、`INV-5010`、`INV-5011`

并在 `ERROR_CODES.md §2.6` 将对应行的 `➕ 新增` 标记改为 `✅ 已固化`（标记是清单的**派生视图**，方向为「随清单改标记」，不得反向）。

### 2.1 为什么一次纳入 6 个而不是按批拆

`INV-5007` 的权限校验落在 `M3-T11`（盘点/手工调整 API），`INV-5008`/`INV-5010` 的冲销端点同属 M3 后续批次。若按批拆成两次 ADR：

- 两次都要改 P0 文档、两次登记、两次全量核对，开销大于收益；
- M3 里程碑内 `B6 → B7` 是连续交付，中间不存在"稳定发布点"，拆开没有降低任何风险。

`ADR-002` 规则 2 的约束是「**里程碑内**同步纳入」，本决策满足且不越界。

### 2.2 常量与逐码定义

- `ErrorCodes.java` 需新增 6 个常量（`INV_5004` … `INV_5011`），命名与既有 `INV_5001` 一致。
- HTTP 状态码、含义、触发条件、处理建议、可重试性**一律以 `ERROR_CODES.md §2.6` 为准**（`§12.3` 只是索引，不定义语义）。
- `INV-5005` 与 `INV-5006` 的边界：**`qty_delta = 0` / 目标值非法 → `INV-5005`（400，请求不合法）**；**调整后 `on_hand_qty < 0` → `INV-5006`（409，业务规则冲突）**。二者不得混用。
- `INV-5007` 与 `TEAM-2003` 的关系：`TEAM-2003` 是通用「角色不足」，`INV-5007` 是库存调整场景的**专门码**。裁定：**库存调整路径统一抛 `INV-5007`**（`INVENTORY_WORKFLOW §5.5` 同时提到两者，取专门码，理由是对前端可给出更精确的提示），`TEAM-2003` 保持用于其它 RBAC 场景。

## 3. 影响与后续

| 项 | 内容 |
| --- | --- |
| 清单规模 | `§12.3` 由 **64** 码增至 **70** 码 |
| 文档改动 | `DESIGN_BASIS §12.3`（+6 行）、`ERROR_CODES.md §2.6`（6 处标记）、`DESIGN_REVIEW` 新增 **R54** |
| 代码改动 | `ErrorCodes.java` +6 常量（由 `B6` 落地，非本 ADR 直接改代码） |
| 风险 | 若 `B6` 实际未用到某码，则该码成为"清单内但无依赖"的**冗余成员**——按 `ADR-002` 规则 2 不违规（规则只约束"漏纳"，不禁止"多纳"），但需在 M3 收口核对时复查，冗余者保留（已被验收项依赖，不作为删除依据） |
| 核对口径 | 沿用 `ADR-003 §2` 的四步法（常量集合 / 真实依赖 / 清单表格行 / 差集），**M3 收口时必须复跑一次** |

## 4. 未采纳的方案

| 方案 | 不采纳理由 |
| --- | --- |
| 让 `B6` 实现时"先不抛这些码"，等 M3 收口再补 | 违反 `ADR-002` 规则 2 的"同一里程碑内同步"；且缺口就是靠"先凑合、后补"累积出来的（`R26` 即此类） |
| 复用 `TEAM-2003` 代替 `INV-5007` | 前端无法区分"角色不足"与"该操作需更高角色"，且 `ERROR_CODES.md` 已把两者分别定义 |
| 用 `COM-0001` 代替 `INV-5005` / `INV-5011` | 参数校验类错误若一律用通用码，会丢失"库存调整"的业务语义，与 `ERROR_CODES.md §2.6` 既有设计相悖 |
