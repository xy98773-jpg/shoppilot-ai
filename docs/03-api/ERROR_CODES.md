| 项 | 内容 |
| --- | --- |

### 本文档负责什么

- 完整给出**全部错误码**：错误码、HTTP 状态、含义、触发条件、**用户可见提示（中文）**、处理建议、是否可重试。
- 给出**错误响应示例**（3 个典型场景）。
- 给出**错误码使用规范**（禁止复用、新增流程、脱敏原则）。

### 本文档不负责什么

- **不定义错误响应体的结构**（见 `API_CONTRACT.md §2.3`；内部接口见 `AI_SERVICE_CONTRACT.md §5`）。
- **不定义状态枚举**（见 `DESIGN_BASIS.md §9`）；本文档"触发条件"只引用。
- **不定义权限判定逻辑**（见 `USER_ROLES.md §4`）；本文档只引用 `TEAM-2xxx` 的出现时机。
- **不定义授权/接口清单**（见 `API_CONTRACT.md §10`）。

## 1. 错误码格式与分段

### 1.1 格式（引用 `DESIGN_BASIS §12.1`）

```
<DOMAIN>-<4位数字>
```

- `DOMAIN`：3 字母业务域缩写。
- 用户可见错误码是**稳定常量**，**不随实现变化**（`DESIGN_BASIS §12.1`）。

### 1.2 业务域分段（引用 `DESIGN_BASIS §12.2`）

| 前缀 | 业务域 | 号码段 | 本文档占用 |
| --- | --- | --- | --- |
| `COM` | 通用 / 参数校验 / 系统 | 0001–0999 | `COM-0001` … `COM-0014` |
| `AUTH` | 认证与登录 | 1001–1099 | `AUTH-1001` … `AUTH-1011` |
| `TEAM` | 团队与权限隔离 | 2001–2099 | `TEAM-2001` … `TEAM-2009` |
| `CAT` | 商品 / SKU / 供应商 / 仓库 | 3001–3099 | `CAT-3001` … `CAT-3012` |
| `IMP` | 数据导入 | 4001–4099 | `IMP-4001` … `IMP-4013` |
| `INV` | 库存 | 5001–5099 | `INV-5001` … `INV-5011` |
| `SAL` | 销售数据 | 6001–6099 | `SAL-6001` … `SAL-6006` |
| `ANL` | 分析任务 | 7001–7099 | `ANL-7001` … `ANL-7013` |
| `RPL` | 补货建议与审核 | 8001–8099 | `RPL-8001` … `RPL-8012` |
| `PO` | 采购与到货 | 9001–9099 | `PO-9001` … `PO-9012` |
| `AI` | **内部**（Java↔Python，非用户可见） | 由本文档定义 | `AI-0001` … `AI-9001` |

> `AI-xxxx` 是 `DESIGN_BASIS §12.2` 之外由本文档**新增的内部域**（Python 服务专用，**不暴露给终端用户**，Java 转换后再决定对外错误码）。见 §2.11 与 §4.4。

**错误码总数**：`COM` 14 + `AUTH` 11 + `TEAM` 9 + `CAT` 12 + `IMP` 13 + `INV` 11 + `SAL` 6 + `ANL` 13 + `RPL` 11 + `PO` 12 + `AI` 17 = **129 条**（其中对外业务错误码 112 条，内部 `AI` 域 17 条）。

### 1.3 标记说明

- **可重试**：`是`（瞬时冲突/并发，刷新或重试可能成功）/ `否`（确定性失败）/ `视情况`。
- **`✅ 已固化`**：表示该码已列入 `DESIGN_BASIS §12.3` 的固化清单，其含义与 HTTP 状态**不得**修改。`§12.3` 是该清单的**唯一权威**，本表标记为**派生视图**；二者不一致时以 `§12.3` 为准，并须修正本表标记。 纳入条件见 `DESIGN_BASIS §12.3` 附注「成员资格规则」（凡被已实现代码或已发布里程碑验收项依赖的码必须纳入；`ADR-002`）。
- **本文档新增**：标注 `➕ 新增`，说明为在既定号码段内扩展。

## 4. 错误码使用规范

### 4.1 禁止事项

1. **禁止复用错误码表达不同含义**（`API_CONTRACT.md §8.2`）。一个错误码**只有一个**语义。
2. **禁止随意新增错误码**。新增必须：
   - 在本文档登记（含 HTTP、含义、触发条件、用户提示、处理建议、可重试）；
   - 若涉及跨文档事实，提交变更并同步 `DESIGN_BASIS.md §12.3`；
   - 更新前端 `types/errors.ts` 映射与测试用例。
3. **禁止在业务代码中硬编码错误消息字符串**：一律使用错误码常量 + 统一异常体系，消息集中维护。
4. **禁止修改已固化错误码的 HTTP 状态或语义**（`DESIGN_BASIS §12.3`）。修正只能**新增**错误码。
5. **禁止把 `AI-xxxx` 透传给前端**（§2.11）。
6. **禁止用 `COM-0002` 兜底所有异常**：能归类的必须归类到具体域错误码，`COM-0002` 仅用于真正的未预期错误。

### 4.2 用户可见 `message` 与内部日志详情的分离

| 维度 | 用户可见（响应体 `message`） | 内部日志 / `detail` |
| --- | --- | --- |
| 语言 | 简体中文（`DESIGN_BASIS §2`） | 可含英文堆栈/技术细节 |
| 内容 | 面向运营人员，**可理解、可行动** | 含异常类名、SQL、参数、`requestId` |
| 技术细节 | **禁止**出现堆栈、SQL、类名、内部路径、`AI-xxxx` | 允许 |
| 敏感数据 | 禁止回显（口令恒为 `***`） | 需与 `audit` 同一脱敏黑名单（`DATABASE_DESIGN.md §6-J.3`） |
| 关联 | `message` + `requestId` | `requestId` 用于把用户报告与内部日志关联 |

**示例（内部日志）**：

```
ERROR [AnalysisAppService] requestId=req_anl_001 teamId=7 userId=1001 uri=POST /api/v1/analysis/runs
cause=AIError(code=AI-3001, detail={stage=RISK_RULES, sku_id=5001})
mappedTo=ANL-7002 status=502
```

### 4.3 不泄露堆栈与 SQL

- 全局异常处理器（`GlobalExceptionHandler`）必须把未分类异常统一映射为 `COM-0002`，响应体**只**含 `message`+`requestId`。
- 严禁把 `SQLException` 的原始消息（可能含表名/列名/条件）放入 `message`。
- 查询参数与请求体中的**敏感字段**在日志中脱敏（字段名黑名单 `password`/`token`/`secret`/`api_key`/`authorization` + 手机号/邮箱正则，与 `audit` 一致）。
- `request_uri` 记录时**必须剥离查询串**（防 `?token=` 泄漏，`DATABASE_DESIGN.md §5.22`）。

### 4.4 错误码 → HTTP → 用户提示 的一致性约束

- 一个错误码**固定**对应一个 HTTP 状态（不可在不同接口返回不同状态）。
- 用户提示**稳定**：同一错误码的 `message` 文案应一致（可加动态后缀，如具体字段名/数量）。
- 对外错误码与内部 `AI-xxxx` 的映射**必须**显式维护在 `AI_SERVICE_CONTRACT.md §5.1` 与本文档 §2.11。

### 4.5 新增错误码流程

1. 提出人确认**现有错误码无法复用**。
2. 按 `DESIGN_BASIS §12.2` 选择域与号码段（在段内递增，不跳号、不复用）。
3. 在本文档对应分节追加一行（6 列齐全）。
4. 若为跨文档事实（如影响 SSOT 的错误码语义），同步 `DESIGN_BASIS.md §12.3` 并记 ADR。
5. 在 `docs/06-development/DESIGN_REVIEW.md` 记录本次变更。
6. 更新前端错误码映射、后端错误码常量类、测试用例。
