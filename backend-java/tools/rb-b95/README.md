## 结论（2026-10-17，`a253520`）

```
RB95_CHECK_TOTAL=36
RB95_FAIL_COUNT=1
RB95_NOTE_COUNT=2
RB95_RESULT=HAS FAILURES; P1-首次不得带重放头(exp=[] act=[true])
```

- **唯一 FAIL 是 `R74`**：`StockChangeResult.idempotentHit` 同时表示「重放命中」与「差额 0 无变更」，
  而 `B9.5` 新增的响应头只认前者 ⇒ 首次无差异盘点被误标为「重放」。修法 1 行（`txnId != null`），
  已排 `B9.6` 微回修。
- **`R72` / `R73` 的修复本身经独立复现成立**：冲销路径同样受同事务保护（`P3`）、
  失败不污染幂等键（`P4`）、跨团队无泄露（`P5`）、重放回放首次值（`P7`）。

## 探针设计要点（写下来防止被误读）

1. **`P1` 只能造「差额 0」才触发**：`attemptCountAdjust` 在 `delta.signum()==0` 时返回
   `idempotentHit=true` 且 `txnId=null`（`§5.5` 步骤 G 不写流水）。开发的「首次无重放头」用例
   用的都是有实际变更的冲销/盘点，恰好绕开该分支 —— 这不是对方写错，是覆盖缺口。
2. **`P4` 的重试必须用同一个 key**：若改成新 key，「重试成功」毫无信息量；用旧 key 才能证明
   「失败时幂等记录随事务一起回滚」。
3. **`P5` 需要先给团队 8 补一行余额**：`seed-b95.sql` 里团队 8 只有主数据没有 `inventory_balances`，
   直接调调整接口会先撞 `INV-5004`，把幂等隔离结论掩盖掉。
4. **`P3` 不能只看状态码**：还要断言「原流水未被标记已冲销」——若回滚只回滚了新流水而留下
   `reversed_txn_id`，状态码同样是 500，但业务已经坏了。
